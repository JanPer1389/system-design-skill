# Протокол поведенческой проверки

`scenarios.json` — входы и критерии, а не результаты. Ни один сценарий не считается пройденным по совпадению слов в SKILL.md. Fixture-код и SQL предназначены только для чтения.

После отдельного разрешения на возможные модельные расходы:

1. Подготовить новый изолированный проект/профиль хоста; установить локальный пакет нативным механизмом. Не подключать credentials, рабочую БД или чужие проекты.
2. Для каждого сценария начать чистую сессию; передать только request, context и перечисленные raw files. Историю из других сценариев не переносить. Для 06/10 использовать явно заданный current-context.
3. Проверить discovery и bootstrap по инструментальным событиям/контексту, затем наблюдаемое поведение. Сохранить запрос, ответы, tool calls, созданные файлы, версии хоста и пакета. Записать невозможность инструмента, если хост не предоставляет соответствующую операцию.
4. В brainstorm ответить на первый раунд; проверить, что зависимые вопросы появляются только после ответов. Для 11 продолжить существующее обсуждение заданным stop-сообщением.
5. Сравнить с каждым expected/forbidden; зафиксировать pass/fail/unknown с цитатой или событием и относительным путём transcript. Отсутствие инструмента не считать успехом соблюдения запрета само по себе.
6. Дополнительно провести no-plugin контроль в отдельной чистой сессии. Он нужен для оценки влияния инструкций, а не для доказательства упаковки.

Текущий статус всех 26 сценариев: **execution unverified**. Автоматические Python/Node тесты проверяют инфраструктурные контракты, privacy примеров и достижимость references, не решения модели. Native CLI validation/install также не доказывают соблюдение навыка. Новые сценарии 14–20 отдельно проверяют доменное исследование, распознавание отношений, framework false positives, два прохода review, design-mandated defects, калибровку, focused re-review и конкретность implementation handoff.

Сценарии 22–26 проверяют самостоятельный выбор инструментов для нетехнического пользователя, переход от карты системы к задачам, видимый план без Plan Mode, условия Mermaid, разделение текущего/целевого состояния, отсутствие renderer/web и соблюдение явных ограничений. Для 24 отправить последующие реплики в той же сессии. Проверять содержательность задач и решений по результату, а не наличие заголовков. Статус: execution unverified.
